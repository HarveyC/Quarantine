# Quarantine

Co-op tactics roguelike: a squad of Carriers fighting an infection that is also their power source.
First playable MVP: one mission, four soldiers, local hot-seat co-op.

## Download and play (no Godot needed)

Grab the zip for your computer from the [Releases page](https://github.com/HarveyC/Quarantine/releases),
unzip it and run the game. Each zip has a `HOW-TO-PLAY.txt`.

- **Windows:** run `Quarantine.exe`. SmartScreen will warn because the game isn't code-signed yet:
  click **More info → Run anyway**.
- **Mac:** move `Quarantine.app` somewhere, then the first time **right-click → Open → Open**.
  If macOS says the app "is damaged" or can't be opened (Gatekeeper quarantine on unsigned apps),
  run once in Terminal: `xattr -cr /path/to/Quarantine.app`.
- **Linux:** run `./Quarantine.x86_64`.

### Publishing a build

Push a version tag and GitHub Actions builds Windows, macOS (universal, ad-hoc signed) and Linux zips
and attaches them to a release:

```
git tag v0.1.0 && git push origin v0.1.0
```

To build locally instead: `release/build.sh /path/to/godot dev` (needs Godot 4.4.1 export templates);
zips land in `build/dist/`.

## Development

- Engine: Godot 4.4 (GDScript)
- Run the game: open the folder in Godot 4.4 and press F5
- Run tests: `./tests/run.sh` (set `GODOT=/path/to/godot` if it is not on your PATH)
- Code layout and module contracts: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)

## Playing the MVP

Launch the game and you get a menu: **Host online game**, **Join** (enter the host's address), or
**Local hot-seat**. In an online game each player controls only their own soldiers and has their own
READY button; the host runs the authoritative simulation. Direct connection is by IP, so over the
internet the host forwards the port (default 24680) or everyone shares a LAN tool like Tailscale.

### Local hot-seat: Player 1 has the Trooper and Marksman, Player 2 the Medic and Breacher. Both act in any
order during the squad phase; the enemy phase runs when both press READY.

| Input | Does |
|---|---|
| Left-click soldier / Tab | Select (Tab cycles soldiers with actions left) |
| Left-click highlighted cell | Move (hover shows path and cover: blue full, yellow half) |
| 1 Shoot, 2 Overwatch, 3 Hunker, 4+ abilities and mutations | Pick an action |
| Tab / Enter or Space (in Shoot) | Next target / fire |
| Space | Ready / unready (for the selected soldier's player) |
| Esc or right-click | Cancel, then deselect |
| WASD, Q/E, wheel, F | Pan, rotate, zoom, focus selected |
| C | Toggle shot cameras (cinematic over-the-shoulder shots) |
| M | Mute / unmute sound |
| F10 | Sound settings (volume per channel) |

Dev flags: `godot --headless -- --autoplay` plays a mission headlessly;
`xvfb-run godot --rendering-driver opengl3 -- --screenshot=out.png [--screenshot-action=shoot|fire|ready] [--screenshot-frame=N] [--seed=N]` saves a frame.
Add Godot's `--fixed-fps 30 --write-movie out.avi` with `--screenshot-action=fire` to record a whole shot
cinematic with sound. Sound effects are generated by `python3 tools/gen_sfx.py`, and the music, ambience and enemy voices by `python3 tools/gen_music.py` (see `audio/CREDITS.md`).
Characters are CC0 Quaternius bodies and animation clips dressed by `tools/build_characters.py`
(see `assets/characters/CREDITS.md`); props come from `tools/gen_models.py`;
`godot -- --lineup=out.png [--lineup-mode=classes|infection|action] [--lineup-kinds=runner,spitter]`
renders a close-up model lineup, and `godot -- --lineup-mode=classes` opens it as a turntable.
Networking can be smoke-tested headlessly with `./tests/net_playtest.sh`, which runs a host and a
client through a whole match and checks they agree. CLI shortcuts: `--host[=port]`,
`--join=addr[:port]`, `--name=...`, `--autostart=N`.
